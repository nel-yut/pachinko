# 実装メモ（設計書との対応・未確定事項）

設計書 `pachinko-foundation-design.md` を要件基準とする。依存パッケージなし（素のES Modules + Canvas）。

## 起動・検証

```
npm run serve          # http://localhost:8080/ （index.html=遊技, verify.html=検証）
npm test               # node:test（ルール検証・統計・物理・再現性）
npm run verify         # CLI検証レポート (--seed N --draws N --launches N --json --out file)
npm run build          # dist/ に静的配布物（検証あり）
npm run build:release  # 検証画面・検証コードを除外した公開版 dist/
```
インフラ（CloudFront/S3/DNS）は変更していない。`dist/` をそのまま既存の静的配信に載せられる形。

## 責務の分離

| 責務 | ファイル |
|---|---|
| 乱数（本番 crypto / 検証 seeded の差し替え） | `src/core/rng.js` |
| 整数抽選・整数重みの振分 | `src/core/lottery.js` |
| 設定検証（不整合/未確定検出） | `src/core/config-validate.js` |
| 保留・変動・大当たり・V・ST・時短・アタッカー・賞球・普図/電チュー（仮想時計） | `src/core/machine.js` |
| 盤面物理（衝突・入賞センサー。抽選を知らない） | `src/physics/world.js`, `layout.js` |
| 物理↔ロジックの接続のみ | `src/game/session.js` |
| 演出（ロジックのイベントを表示するだけ・差し替え可） | `src/effects/placeholder-pack.js` |
| 描画 / 入力 / HUD | `src/ui/render.js`, `main.js` |
| 検証（集計・理論値・ルール・抽選MC・高速試行・物理レポート） | `src/verify/*` |
| 機種データ | `src/presets/*.js` |

イベントの流れ: 物理が「どの玉がどの口へ」を返す → `machine.ballEntered`（1玉1回）→ 始動口なら**この瞬間だけ**抽選して保留へ。
発射・ゲート通過・アウト・変動開始・演出では抽選しない（R01/R02 で検証）。

## 設計書要件の実装状況

- 抽選: 整数分子/分母（`rng.nextInt(den) < num`、棄却法でバイアスなし）。特図1/2は確率・保留・振分を別設定。入賞時に結果を保留へ保存、変動後に消化。保留上限・優先順位(sp2First/sp1First/fifo)・ST終了時残保留(consume/discard)は設定化。
- 状態: 通常/時短/ST/大当たり中。ST・時短は特図の変動回数で消化。ST中大当たり＋V入賞でST再設定、V無しは設定の afterNoV。
- アタッカー: 規定入賞数または時間で閉鎖処理開始 → 閉鎖遅延(closeDelayMs)中に**実際に入った玉**をオーバー入賞として計数・賞球。規定数到達で盤面の玉は消さない。
- 出玉: 発射ごとに持ち玉-1、入賞ごとに即時加算。
- 左打ち/右打ち: 発射強度で物理的に経路が変わる（弱=左側へ落下、強=外レールを回り右側へ）。右側のゲート通過→普図抽選→電チュー開放→特図2始動口。
- 検証: ルール16項目、抽選統計（理論/実測/95%区間/z）、遊技フロー高速試行（machine同一ロジック・仮想時計・到達モデル）、物理到達率（強度別）。抽選検証と物理検証は別レポート。
- 公開可否: `src/config/features.js` の `FEATURES.verification` または `npm run build:release`。

## 盤面・見た目（実機寄せ v2）

- **盤面**: 外レール/内レール、中央の大型液晶枠（屋根・左側面のワープ入口・ステージ）、風車×3（玉の衝突で回る）、命釘・寄せ釘・流れ釘、ゲート(チェッカー)、電チュー(開閉ウイング)、賞球口(肩・袖・ベース×6、フード付き)、アタッカー(開閉扉・V)、ハカマ・アウト口。座標は `src/physics/layout.js` の `DEFAULT_BOARD_PARAMS` で変更可能。
- **ステージ**: ワープに入った玉が液晶下のステージ床へ移り、中央の穴からヘソ方向へ落ちるか、端からこぼれる（玉の勢い次第）。
- **ハンドル**: 盤面下のダイヤルをマウス/タッチでドラッグして強度調整＋発射（スライダーと「押している間 発射」ボタンも併用可）。発射強度→初速は区分線形で、弱＝左打ち域、強＝右打ち域。
- **筐体**: 上皿(持ち玉)・下皿(賞球累計/発射数)。
- **演出**: 液晶(特別図柄3桁・リーチ・保留ランプ・ラウンド/カウント表示・状態別の背景)と、液晶枠の手前で動く大型役物(翼・紋章)。いずれも図形のプレースホルダーで、遊技ロジックのイベントを表示するだけ。見た目の抽選結果の演出(リーチ等)は見た目専用の乱数で、当落には関与しない。
- 版権画像・既存機種の画面・ロゴは使っていない（盤面の絵柄も抽象図形）。

## 設計上の判断・既知の制約

- 大当たり中の入賞の抽選確率区分は設定項目 `lottery.probDuringJackpot`（サンプルは low）。実機の挙動は未確認のため設定化した。
- ST突入時に残っている保留は入賞時の確率で抽選済みのため、「ST継続率の理想値」(1-(1-p)^N)より実測は低くなる。レポートに併記。
- V入賞成功率は盤面物理（または到達モデル）の結果であり、抽選確率ではない。ST突入率（直行）はこれに依存する。
- 発射強度の目安: 0.15〜0.3 付近が左打ち、0.6 以上が右打ち（間は混在）。0.1 以下は発射レールを昇れず戻る。
- 玉同士の衝突は未実装（軽量化のため）。物理パラメーター・釘/部品座標は `board.params` で上書き可能。
- 高速試行の玉到達は `fastsim.js` の `DEFAULT_REACH`（口ごとの整数重み）で近似。物理レポートの数値から調整する別設定であり、抽選確率とは無関係。
- 確変ループ・1種2種混合は未実装（`afterV`/`afterNoV` の `mode` と `machine.js` の状態遷移に追加する形で拡張可能）。
- 状態の永続保存・複数端末同期は対象外。
- 演出差し替え: `src/effects/placeholder-pack.js` の EffectPack インターフェースを実装した別オブジェクトに置換する。版権素材は含めていない（図形のみ）。
